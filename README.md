# 퀴즈 배틀 — 실시간 퀴즈쇼

관리자가 퀴즈쇼를 만들고, 참가자가 6자리 코드+닉네임으로 접속해 20초 제한
실시간 퀴즈를 풀며 순위를 겨루는 웹앱.

## 1. Firebase 설정
1. https://console.firebase.google.com 에서 새 프로젝트 생성
2. 빌드 > Realtime Database 만들기 (위치 선택, "테스트 모드"로 시작)
3. 프로젝트 설정 > 내 앱 > 웹 앱 추가 → firebaseConfig 값 복사
4. `js/firebase.js` 상단 `firebaseConfig`를 복사한 값으로 교체
5. Realtime Database > 규칙에 아래 규칙 적용(내부/워크숍용):

    {
      "rules": {
        "quizzes":    { ".read": true, ".write": true },
        "quizImages": { ".read": true, ".write": true },
        "rooms":      { ".read": true, ".write": true }
      }
    }

   **`quizImages`를 빠뜨리면 문제 이미지 저장이 `permission_denied`로 막힙니다.**
   (한 프로젝트를 여러 앱이 나눠 쓴다면 다른 앱의 경로는 지우지 말고 그대로 두세요.)
   공개 배포 시 보안 규칙 강화 권장 — 아래 11절 참고.

## 2. 관리자 암호
`js/config.js`의 `ADMIN_PASSWORD` 상수를 원하는 값으로 변경.
강사 화면(진행)과 전체 순위 창이 함께 씁니다.

## 3. 로컬 실행
정적 파일이라 브라우저로 열면 되지만, ES Module CORS 때문에 로컬 서버 권장:
`npx serve .`  또는  `python -m http.server 8000`

> **로컬 테스트 주의** — `npx serve`는 `/index.html?room=코드` 주소를 `/index`로
> 리다이렉트하면서 `?room=` 부분을 버립니다. QR 자동 입력을 로컬에서 시험하려면
> `/?room=코드` 형식을 쓰세요. GitHub Pages에서는 그대로 동작합니다.
>
> 폰으로 QR을 찍어 시험하려면 `localhost`가 아니라 PC의 내부 IP로 여세요
> (예: `http://192.168.0.10:4321/`). QR에 그 주소가 담깁니다.

## 4. 주소는 하나만 씁니다
워크숍에서 외울 주소는 배포 주소 하나뿐입니다. 들어온 경로에 따라 화면이 갈립니다.

| 주소 | 보이는 화면 |
|---|---|
| `/` | 교육생 입장 + 구석에 `강사용 →` |
| `/?room=8K2QY7` | 교육생 입장, 방 코드 자동 입력 (QR이 이 주소를 담습니다) |
| `/?results=8K2QY7` | 강사 전용 전체 순위 (시상대 화면의 버튼이 새 창으로 엽니다) |

강사는 기본 주소로 들어가 `강사용 →`을 누르면 됩니다. `?host=1`·`?results=`는
직접 입력하는 주소가 아니라 버튼과 예전 주소 이동에 쓰입니다.

예전 주소 `admin.html`·`results.html`은 파일을 남겨 두고 새 주소로 자동 이동시킵니다
(메모해 둔 주소나 즐겨찾기가 깨지지 않도록).

## 5. 결과 화면 구성
| 보는 사람 | 화면 | 내용 |
|---|---|---|
| 모두 (프로젝터) | 진행 화면의 최종 결과 | 1·2·3등 시상대만 |
| 강사 | `?results=코드` (새 창) | 전체 순위 + 맞힌 개수 + CSV |
| 교육생 각자 | 교육생 화면의 최종 | 내 등수 / 점수 / 맞힌 개수 |

강사 노트북과 프로젝터를 **확장 디스플레이**로 쓰세요. 미러링 상태면
전체 순위 창도 프로젝터에 그대로 보입니다.

## 6. 순위 기준
- **문제별 순위** — 그 문제를 **빨리 맞힌 순**(정답 + 제한시간 내). 오답자는 빠집니다.
- 점수는 `100 + 속도보너스(최대 100)`, x2 문제는 2배. 같은 문제 안에서는
  "빨리 맞힌 순 = 점수 많이 받은 순"이 항상 일치합니다.
- **최종 순위** — 누적 총점. 동점은 닉네임 가나다순.

## 7. 테스트
`node --test`  (순수 로직 검증 31개 — 채점·순위·엑셀 변환)

## 8. 엑셀로 여러 문제 한 번에
편집기 맨 아래 `엑셀 파일에서 여러 문제 가져오기`로 .xlsx 파일 하나를 올리면
그 안의 줄 수만큼 문항이 **현재 퀴즈쇼 맨 뒤에 붙습니다.** 10줄이면 10문항입니다.
(이미지와 달리 문항마다 붙이는 게 아니라 퀴즈쇼 전체에 하나입니다.)

서식은 `template/quiz-template.xlsx` — `서식 내려받기` 버튼이 이 파일을 받습니다.
`문제` 탭만 읽고, `작성 안내` 탭에는 설명과 예시가 들어 있습니다.

| 열 | 적는 내용 |
|---|---|
| 유형 | `객관식` / `OX` / `단답형` |
| 문제 | 문제 내용 |
| 보기1~4 | 객관식만. 앞에서부터 2개 이상, 빈칸 없이 |
| 정답 | 객관식은 보기 **번호** 1~4 · OX는 `O`/`X` · 단답형은 인정 답안을 **쉼표로** 나열 |
| x2 | 2배 점수면 `O`, 아니면 빈칸 |

- **한 줄이라도 잘못되면 아무것도 가져오지 않습니다.** 행 번호와 함께 무엇이
  잘못됐는지 알려주니 엑셀에서 고쳐 다시 넣으세요. 일부만 들어가면 무엇이
  빠졌는지 나중에 찾기 어렵기 때문입니다.
- 가져온 뒤에도 편집기에서 고칠 수 있고, **`저장`을 눌러야 실제로 저장됩니다.**
- 이미지는 엑셀로 넣을 수 없습니다(셀 값이 아니라 떠 있는 개체라서). 가져온 뒤
  필요한 문항에만 편집기에서 끌어다 놓으세요.
- 변환 규칙은 `js/excel.js`의 `parseRows`에 모여 있고 `test/excel.test.js`가 검증합니다.
  엑셀을 읽는 SheetJS(880KB)는 **버튼을 누를 때만** 내려받아 교육생 화면에는 딸려가지 않습니다.

## 9. 문제 이미지
편집기의 문항 카드에 이미지를 끌어다 놓으면 브라우저에서 줄여(긴 변 1280px, JPEG)
Realtime Database의 `quizImages/` 경로에 저장합니다. Firebase Storage는
결제 계정(Blaze)을 요구하므로 쓰지 않습니다.

- 한 장당 400KB를 넘지 않게 자동으로 압축합니다. 못 맞추면 더 단순한 이미지를 요청합니다.
- 이미지는 **방(`rooms/`) 안에 넣지 않습니다.** 방은 참가자 전원이 실시간 구독 중이라
  점수가 바뀔 때마다 이미지까지 다시 내려가게 됩니다. 이 구조를 바꾸지 마세요.
- 무료 요금제 한도는 저장 1GB / 월 전송 10GB입니다. 워크숍 1회(24명 × 10문항)가
  약 50MB이니 여유가 있지만, 자주 쓰신다면 Firebase 콘솔 >
  Realtime Database > 사용량에서 한 번씩 확인하세요.

## 10. 배포 (GitHub Pages)
1. GitHub에 저장소 생성 후 푸시
2. Settings > Pages > Source: master 브랜치 / root
3. 발급된 URL 하나만 쓰면 됩니다 — 4절 참고

## 11. (선택) 보안 규칙 강화
워크숍 종료 후에는 quizzes 쓰기를 잠그는 등 규칙을 조정하세요.

### 신뢰 경계 안내
개방 규칙을 그대로 사용하면 참가자 점수와 답안 제출 시각은
전적으로 클라이언트를 신뢰하는 구조이며 위조가 가능합니다 — 예를 들어 능숙한
사용자가 브라우저 개발자 도구로 자신의 점수 값을 직접 조작할 수 있습니다.
따라서 이 앱은 친목/워크숍용으로만 사용하시고, 경쟁적인 용도로 쓰려면 Realtime
Database 보안 규칙을 반드시 강화하세요.
